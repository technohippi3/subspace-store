# Native certificate export

This public-pilot extension adds explicit native libveritas 0.4.4 export profiles and certificate-only URLs. It preserves the existing raw certificate.message route and the controller's original certificate verification. It does not qualify any unidentified mobile app build. The pinned historical public app schema is incompatible with these native formats; neither unknown profiles nor a legacy JSON wrapper are exported.

The spacecert-v1 profile is the official CertificateChain SCRT container version 1, filename certificate.spacecert. It contains final native root and leaf certificates. The spacemsg-0.4.4 profile is an official native Message reconstructed and verified with the original anchored chain proof, filename certificate.spacemsg. Both use application/octet-stream. The JSON manifest describes these profiles and their exact hashes; it is not a mobile import certificate.

The exporter uses its own Cargo.lock, rust-toolchain 1.94.1, exact libveritas 0.4.4 and spaces_nums 0.4.2. It independently verifies the saved original Message with operator-configured spaced anchors, then checks sovereign handle, recipient script, commitment root and height against the already accepted store record. Official native decoding, certificate serialization, MessageBuilder and another verification must preserve the public verification facts. No JavaScript Borsh, proof reconstruction or custom cryptography is supplied.

An optional exact certificateExport member on version 2 configuration names trustedOrigin, binary, artifactManifest, directory, ttlSeconds and spaced {url,cookiePath}. Version 1 remains regtest-only and unchanged; absent configuration disables all new endpoints and links. The origin requires HTTPS, except explicit regtest loopback HTTP. Release configuration must bind trustedOrigin exactly to the separately reviewed publicOrigin and both paths to the signed exporter and its manifest. Incoming Host and forwarding headers never supply an origin.

Anchors come only from bounded, configured loopback spaced RPC. Each exact root-anchor record must name a distinct descending height and active configured Core block. Its nums_root may be null under the official spaced schema; that absence stays null, and native verification still decides whether the proof has the required roots. Core identity/readiness and the complete tip must remain coherent before and after observation. The request, Message and browser never supply a trust root. Anchor observation is bounded to 512 records, 1 MiB and ten seconds. Native work uses one worker, at most eight queued requests, ten-second subprocess limits and one-MiB output bounds.

A random 256-bit certificate token is separate from full order authority. Only its SHA256 is stored. A grant fixes order, entry, verification revision, original Message hash, root, height, recipient, handle, one native profile and the generated artifact hash. Creation replaces at most one prior slot for the same order/profile. Expiry is an explicit one-to-86400 seconds; the journaled clock cannot move backward. The capability reveals only its native artifact, format manifest, QR and view. It authorizes no order inspection, invoice, cancellation or refund destination.

The strict certificate_capabilities/global record uses the existing primary SalesStore projection, queue, changed-record commit and off-host journal. Existing histories default to an empty ledger without a SQL migration. Creation, clock advancement, rotation and revocation return success only after live journal acknowledgement. Any local pending mutation blocks cap reads until authorized primary observation or mutation retries durable readback. Capability reads do not flush a pending outbox. Unknown and already retired tokens never persist clock changes. The first observation of an authentic expired token atomically advances the clock and retires that grant, with live acknowledgment before a final unavailable response. Later backward time or host replay cannot revive that observed expiry; repeated retired reads write nothing. An unacknowledged reply remains unknown; it cannot imply final revocation or a usable URL. Acknowledged revocation restores with the same order history, and normal application restore quarantine remains in force.

Every scoped read rechecks the same current certificateBytes acknowledgement, cache, finality, root and chain gate as the original order route. A cache hit supplies no independent authority. Cached native bytes and metadata are compared to a real native verification result once per binding/process, plus the grant's fixed artifact hash. Corrupted cache content is discarded and reconstructed; it is never served. A final readiness check after native work refuses an invalidated or revoked grant. A new verification revision never revives an old URL.

The scriptless browser offers both native formats, creates a separate expiring certificate-only view and locally generated QR, and allows the private order holder to revoke every grant. The QR contains the certificate-only download URL and uses no relay. A native profile is not claimed to be an app import format. All routes use no-store, no-referrer, nosniff and script/framing-denying CSP; strict forms use the existing exact byte bound and fatal UTF8 decoder. Diagnostics contain no token, subprocess output or payment request.

The independent deterministic certificate-capabilities model governs scope, rotation, expiry, exact current revision and durable/pending revocation. Native proof, process, HTTP, configuration and actual journal replay requirements are runtime lifecycle rules qualified by integration tests. Model results are not native consensus, regtest, QR scanning or mobile acceptance evidence.
